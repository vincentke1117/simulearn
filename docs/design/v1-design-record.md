## 2. 验收终点

### 2.1 试点：知帆拓展 `simulearn-grid` 0.5.0

试点只嵌入、不判分（Q33 = a）。逐条可验收：

1. 在一台 CPU 与开发机不同的电脑上（或干净虚拟机里），知帆 0.11.0 客户端能从下载站装上拓展，并能启动它。
2. 冷启动时间：目标 ≤ 20 s，硬上限 120 s（宿主最多等 120 s）。
3. 学生在第十二章那一讲点「开始实验」后，打开的是例 12-3 风格的降压变电所算例。学生能做的操作：改分接头挡位、投切电容组、重算潮流。
4. 结果同时显示 kV 和标幺值。
5. 拓展对没带令牌的请求一律返回 401。
6. 标准输入关闭后，拓展在 5 s 内退出。
7. 拓展只写 `--data-dir` 指定的目录。
8. 「个人中心 → 拓展」里能打开第三方许可清单。
9. 「我已完成」和「先跳过」两条路径都走通（不判分实验的规则见约定 §6）。
10. 例 12-3 的金标准契约测试通过：最大、最小负荷两种运行方式下，低压母线电压都落在 6.0～6.6 kV，并选出 107.25 kV 挡。

## 3. 架构决定

### 3.1 运行时与宿主（按 `zhifan-ext/1`）

#### 运行时包

**每间实验室都打成一个约定形态的拓展包**：`simulearn-grid`、`simulearn-lab`。包内包含：

- `bin/<id>.exe`：启动程序
- 最小化的 Julia 1.12.1 运行时
- 预编译镜像（sysimage 或 pkgimage）
- 用到的二进制库
- `ui/`：前端构建产物
- `LICENSES/index.html`：第三方许可清单

启动程序按约定 §2 行事：

```
<entry> --port 0 --token <32 字节十六进制> --data-dir <目录> --host-version <版本>
```

- 只绑 `127.0.0.1`。
- 就绪后打一行 `{"ready": true, "port": …, "version": …, "contract": "zhifan-ext/1"}`。
- 标准输入关闭后 5 s 内退出，并带走 Julia 子进程。
- 只写 `--data-dir`，不联网。

启动程序用 PackageCompiler `create_app` 直接产出的 `bin/<id>.exe`（M0 spike 定）：它本身就是 Julia 进程，可以直接打 ready 行、监听标准输入，不起子进程。另一种做法是「小启动器 + julia.exe」，但产物里 `julia.exe` 和同一份镜像本来就在，体积和启动时间都一样，反而多一层进程，所以不采用。构建用增量模式（`incremental=true`），原因见修订记录。

#### 页面与接口

- 页面和接口都由拓展进程自己提供：静态页面挂在 `/ui/`，接口挂在 `/api/…`。
- 页面里**只用相对路径**：页面在宿主里实际位于 `/ext/<id>/ui/`。
- 不用 WebSocket，不用 Cookie。

#### 宿主

| 宿主 | 阶段 | 职责 |
|---|---|---|
| 知帆客户端 ≥ 0.11.0 | 试点起 | 下载、校验、启动、转发并注入 `X-Zhifan-Ext-Token`、嵌入、记成绩 |
| Tauri 桌面版 | v1.0（M2） | 实现约定的宿主一侧（课程与成绩部分除外）；另外负责原生窗口、文件对话框、凭据库、AI 调用、起始页 |
| 开发态 | 一直 | `scripts/start-all.ps1` + Caddy；Caddy 转发时注入固定的开发令牌 |

**桌面版的细节**

- **转发层**：用 Caddy sidecar 还是 Rust 自写，**推迟到 M2 开工时定**，那时有 spike 的数据。无论选哪种，都要按约定 §3 做到：去掉请求里的 Cookie、拦下响应里的 `Set-Cookie`、注入令牌。
- **端口**：两个内核各用 `--port 0` 自选端口。桌面宿主自己的转发端口优先用 8100，被占用时自动改用空闲端口（Q26）。
- **单实例**：单实例锁。
- **关窗**：关窗即关闭各拓展的标准输入，5 s 内不退就强杀。

#### 预算（Q35，分两档）

| 档 | 目标 | 硬停线 |
|---|---|---|
| 知帆拓展包（只有配电网） | 下载 ≤ 1.2 GB、解压后 ≤ 3 GB、冷启动 ≤ 20 s、首次潮流 ≤ 1 s、内存 ≤ 1.5 / 2 GB | 冷启动超过 120 s，或在第二台电脑上跑不起来。只有碰到硬停线才回头重新评估路线，其余数字超了只是要优化 |
| 桌面完整版（两间实验室） | 安装包 ≤ 2 GB、首启 ≤ 120 s 且全程有进度、二次启动 ≤ 30 s（Q14） | — |

### 3.2 前端：共享壳层 + 嵌入模式（Q10、Q22）

**共享壳层**

- 新建 `packages/shell`（React）。lab-web 直接使用；grid-web 挂一个 React 孤岛来渲染外壳，JointJS 画布原地不动。
- 壳层统一提供：菜单 / 顶栏、工程对话框、最近打开、设置、帮助、toast、错误边界、后端就绪状态、主题 token、快捷键表、撤销栈。
- 默认浅色主题；深色主题放到 v2。

**嵌入模式 `#/embed`**（约定 §4）

- 试点阶段先直接做在 grid-web 里，M1 再收进壳层，成为壳层的一种模式。
- 协议：页面发 `ready`，宿主回 `load`（`experiment` / `project` / `task`），出错时页面发 `error`。
- 界面：只认 `event.source === window.parent` 发来的消息；隐藏导出和文件菜单（iframe 沙箱禁止下载）；界面适应宿主给的舞台大小。
- 本地存储：按实验 id 隔离，键名形如 `slp:grid:exp:<experiment>:*`。
- 允许改什么见 D19。

### 3.3 工程文件与持久化（Q24，桌面版）

- **格式与扩展名**：扩展名 `.slp`，安装器注册文件关联，双击直接打开。格式沿用 `simulearn.project/1`：新元件、仪器、三相都作为 payload 内的扩展。只有真正不兼容时才升 `/2`，并附迁移。知帆 `load` 消息里的 `project` 用的是同一个信封。
- **默认目录**：`文档\SimuLearn\`，首次保存时创建。
- **自动保存**：改动后防抖 2 s，写入 `%APPDATA%\SimuLearn\drafts\<lab>.slp`。非正常退出后，下次启动询问是否恢复。显式保存后清除草稿。标题栏用 `*` 标示未保存。
- **最近打开**：最多 10 条；文件已不存在时灰显，可移除。

### 3.4 内核扩展

#### 电网：教材元件（Q36，试点 P2 就做）

- **变压器连线**：
  - 两侧额定电压。
  - 分接头写成「中心挡 ± 挡数 × 每挡百分比」（如 110 ± 2 × 2.5%），并记录当前挡位。
  - 阻抗归算到高压侧。
  - 后端映射到 PowerModels 支路的 `tap`（非标准变比）。
- **并联电容组**：组数 × 每组容量，并记录当前投入组数。后端映射到现有的并联导纳 shunt。
- **结果显示**：各母线电压同时显示 kV 和标幺值。
- 发电机无功上下限、母线电压等级后端已经支持，前端补齐编辑即可。

#### 电网：任务与判分（Q37）

- 格式 `simulearn.task/1`，按建议文档 §3.4 的草案定稿：
  - `allow` 白名单：限定学生能改哪些元件的哪些参数。
  - `objectives`：每个目标算一关。
  - `hints`：提示。
- 判定在后端新接口 `POST /api/grid/grade` 里做：按学生最后提交的参数重算一遍再核对，不信页面报的数。
- 成绩按约定 §5 回传：`maic-interactive` 协议，`levels` 为目标数，`passed` 为达成数，`raw` 放每个目标的判定结果。
- 第一版只做 6 种检查：
  1. 母线电压范围
  2. 支路功率 / 电流上限
  3. 网损上限
  4. 分接头挡数
  5. 补偿容量上限
  6. 经济调度的出力或 λ 与参考值的误差
- 任务文件放在知帆课程包里；SimuLearn 只负责格式校验、判分，以及契约测试用的示例任务。以后加检查种类只加可选字段。
- **实现时间**：P3 或 M3，见 Q40。

#### 电网：MATPOWER 与 PV / QV（Q18、Q19、Q36）

- **MATPOWER 导入**：PowerModels `parse_file` 读 `.m`，再新写「PowerModels 字典 → 拓扑 JSON」反向转换。**带变比 / 移相的支路导入成变压器元件**（Q36 修订了 Q18 原先的「给线路加 `tap` / `shift` 参数」）。IEEE 14 / 30 / 57 / 118 进示例库。
- **PV 曲线**：逐步加负荷，二分逼近鼻点；加负荷方式可选全网等比例或指定母线。
- **QV 曲线**：在指定母线挂虚拟调相机，扫电压读无功。
- **金标准**：两母线系统的闭式鼻点。
- 连续潮流 CPF 放到 v1.1。

#### 电路：非线性器件（Q15）

器件模型取教学级：Shockley 二极管、Ebers-Moll BJT、Level-1 MOSFET、理想运放。

各分析路径的处理方式：

| 分析路径 | 处理方式 |
|---|---|
| 直流工作点 | 新写 Newton-Raphson；教学模式展示每次迭代 |
| 交流相量 / 频扫 | 先求工作点，再做小信号线性化（gm、rπ、ro） |
| 瞬态 | MTK 原生非线性 |
| 节点电压 / 支路电流 / 网孔 / 戴维南 | 二极管按理想 / 恒压降处理，走假设状态法；BJT / MOSFET 拒绝，并提示改用直流工作点 |

运放的有限增益 / 饱和放到 v1.1。

#### 电路：变压器 / 互感 / 三相（Q17，做全）

- 理想变压器（匝比 n）、互感（L1、L2、k）：支持相量与瞬态（自写 mtkmodel）。直流类分析见 D5。
- 三相：
  - 三相源：A / B / C / N 四端，参数 Vrms、f、相序。
  - 单相交流源在前端暴露相位参数（后端已支持 `phase`）。
  - 三相负载（Y / Δ）。
  - 线电压 / 相电压切换、对称分量、三相功率汇总。
  - 相量图能画三相。

#### 电路：虚拟仪器（Q16）

- 三件仪器：万用表（V / I / R，直流 + 有效值）、双通道示波器、波特仪。
- 运行内容 = 顶栏所选方法 ∪ 图上仪器各自需要的方法，按顺序发请求。
- 结果面板显示顶栏方法的结果，仪器各显示各的读数。
- 函数发生器放到 v1.1。

#### 教学层 T1（Q21）

| 实验室 | 展示求解步骤的方法 |
|---|---|
| 电路 | 节点电压（已有）、支路电流、网孔、戴维南、直流工作点（含 Newton 迭代表）、交流相量（复数 MNA） |
| 电网 | 教学版 NR 潮流（自写，逐次给出不平衡量、Jacobian、修正量，同时作为潮流的第二套对拍；用例 11-5 逐次迭代做金标准）、短路戴维南等值步骤、OPF λ / 影子价格解释 |

## 4. 发布与运维（Q27–Q29）

**知帆拓展**

- `scripts/release-ext.ps1` 打出 `simulearn-grid-<版本>.zip`，内含 `bin/`、`ui/`、`LICENSES/`。
- 清单里的 `bytes` / `sha256` / `unpackedBytes` 由知帆的 `downloads-worker/sync.mjs --ext` 从 zip 本身算出，不手填。
- 上传到 `dl.zhifan.xyz/desktop/ext/`，**清单最后传**。单文件超过约 300 MB 时，走 R2 的 S3 接口上传。

**桌面版**

- **构建**：本机 `scripts/release.ps1` 一键构建安装包，上传 GitHub Releases，附 SHA256。CI 出安装包放到 v1.1。
- **签名**：v1 不签名；README 和下载页写清楚怎么点过 SmartScreen。v1.0 发布前再评估是否买证书。
- **更新**：手动。「关于」里放「检查更新」，链到 GitHub Releases。自动更新放到 v1.1。

**共同**

- **遥测**：零遥测，原则上永不做。
- **日志**：知帆宿主会把拓展的标准输出写进它自己的日志。桌面版自己写本地滚动日志，并提供「导出诊断包」（zip）按钮。
- **CI**：只做 lint / test / 前端构建 / Julia 测试。

## 7. 风险

| # | 风险 | 应对 |
|---|---|---|
| R1 | Julia 的 sysimage / pkgimage 如果按构建机 CPU 编译，在学生的老 CPU 上会失效，并在现场重编，直接打破冷启动预算 | spike 已用多目标 `generic;sandybridge,-xsaveopt,clone_all;haswell,-rdrnd,base(1)` 构建，本机（Arrow Lake）验证通过。**换一台 CPU 不同的电脑还没验证**，验证套件见修订记录 |
