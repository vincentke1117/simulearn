# SimuLearn 独立产品开发建议

2026-10-13。给 SimuLearn 的开发管线用。背景见《仿真平台对接评估》（只读评估，§6 为客户端拓展方案）。结论：**SimuLearn 作为独立产品开发，在知帆客户端里以可选拓展的形式集成。** 代码、版本、发布、许可都归 SimuLearn 自己；知帆只负责下载、启动、嵌入和记录成绩。

仓库：`D:\workspace\projects\simulearn`（GitHub `vincentke1117/simulearn`），评估时的提交 52d63ae。

## 1. 定位与边界

- **是什么**：通用的电气工程仿真实验软件（电路 + 电力系统），可以单独使用（本机网关 `127.0.0.1:8100`），也可以作为宿主程序的拓展运行。
- **不知道「课程」**：账号、课程内容、学生、成绩存储都归宿主（知帆）。SimuLearn 只做三件事：打开宿主交给它的算例和任务、跑仿真、按任务判定并回传结果。教材算例、实验任务属于课程内容，由知帆放在课程包里，打开时交给 SimuLearn。
- **平台**：Windows x64 优先（知帆客户端只出 Windows 版）。
- **先做配电网实验室**（PowerModels 栈）。电路实验室（MTK 栈，285 个依赖、PackageCompiler 构建失败、首次瞬态 3.6 秒）先不进拓展，继续作为开发 / 单机工具；等第二门课（电路、控制、暂态）需要时再评估。

## 2. 第一阶段：能分发（最先做，决定这条路成不成）

### 2.1 可移植打包（1～2 天的验证，先于一切）

现在的 `packages/grid-backend/sysimage/grid.sysimage.dll`（711 MB）是按开发机 CPU 编译的，**换一台 CPU 不同的电脑可能直接崩**，不能拿去分发。

- 用 PackageCompiler 重新构建，指定通用 CPU 目标，例如 `cpu_target = "generic;sandybridge,-xsaveopt,clone_all;haswell,-rdrnd,base(1)"`（Julia 官方发行版用的多目标写法）；或用 `create_app` 做成独立程序。两种都试，比较体积和启动时间。
- 包里放：最小化的 Julia 运行时 + 预编译镜像 + 用到的二进制库（Ipopt、MUMPS、HiGHS、OpenBLAS 等）+ `grid-web` 构建产物 + 一个启动程序。
- **必测的数字**（在开发机和另一台 CPU 不同的干净 Windows 上各测一遍；没有第二台就先用 Windows 沙盒）：

| 指标 | 期望 |
|---|---|
| 下载（压缩后） | ≤ 1.2 GB |
| 解压后 | ≤ 3 GB |
| 冷启动到健康检查通过 | ≤ 20 秒 |
| 第一次潮流请求 | ≤ 1 秒 |
| 内存（空闲 / 峰值） | ≤ 1.5 GB / 2 GB |
| 杀毒软件、SmartScreen | 不被拦截，或明确需要什么签名 |

数字明显超出就停下来，回到服务器部署方案（评估文档 §4）。

### 2.2 运行时加固（作为拓展运行时必须满足）

- 只绑 `127.0.0.1`；端口由宿主指定，或传 `0` 由程序自选，就绪后在标准输出打一行 JSON 告诉宿主（见 §3.1）。
- 所有 `/api/*` 请求校验宿主给的随机令牌（请求头 `X-Simulearn-Token`），不对就拒绝——防止学生电脑上的其他网页偷偷调用本机端口。不开 CORS。
- 只写宿主指定的数据目录（日志、运行记录），不写安装目录，不写用户其他位置。
- 标准输入关闭或收到退出请求时干净退出；同一数据目录只允许一个实例。
- 不主动联网（隐私；离线可用）。

### 2.3 许可证

分发给学生意味着要履行依赖的许可义务：

- 生成第三方许可清单：Julia 本体和标准库、`Manifest.toml` 里的全部包、所有 artifact（二进制库），附许可原文。
- 逐个核实有附加义务的组件，例如 Julia 官方发行版里 SuiteSparse 的 GPL 部分、Ipopt 依赖的 MUMPS（CeCILL-C）、JuMP 与 JointJS（MPL-2.0）、Ipopt（EPL-2.0）；需要提供源码获取方式的写明从哪里获取。
- 定下 SimuLearn 自己的许可方式（闭源 / 开源）。知帆是闭源、将来可能收费的产品，两者是通过本机地址通信的独立程序，互不影响。

## 3. 第二阶段：和宿主的对接约定（v1 草案）

知帆这边定稿后写进知帆仓库，带版本号（`zhifan-ext/1`）。两边各自升级时不能打破它。

### 3.1 启动

```
simulearn-grid.exe --port 0 --token <随机令牌> --data-dir <宿主指定目录>
```

就绪后在标准输出打一行：

```json
{"ready": true, "port": 51234, "version": "1.0.0", "contract": "zhifan-ext/1"}
```

宿主读到这一行才打开页面；启动失败打 `{"ready": false, "error": "…"}` 后退出。

### 3.2 打开实验

- 页面地址：`http://127.0.0.1:<port>/grid/#/embed`。**嵌入模式**：隐藏工程管理、文件菜单这类与实验无关的功能；不写 `localStorage` 里的工程数据（或按实验 id 隔离）；中文界面；适应宿主给的窗口大小。
- 页面加载后向父窗口发 `{"source": "simulearn", "type": "ready"}`；宿主回 `{"source": "zhifan-host", "type": "load", "project": <算例>, "task": <任务>, "origin": <宿主页面的 origin>}`。算例沿用现有的 `simulearn.project/1` 工程文件信封。内置算例也可以用 `#/embed?example=<名字>` 直接打开。
- 页面只接受来自 `load` 消息里 `origin` 的消息。

### 3.3 回传成绩（沿用知帆现有的互动成绩协议）

完成任务（或每次判定）时：

```js
parent.postMessage({ source: "maic-interactive", type: "score", score, maxScore,
  detail: { levels, passed, perfect, raw } }, hostOrigin);
```

- 知帆播放器只认这个格式，并校验消息来自当前挂载的那个 iframe；字段名必须一致。
- 知帆判「通过」时**优先看 `detail.levels` / `detail.passed`**（通过的关卡数 ≥ 60% 算通过），没有时才看 `score / maxScore`。所以一个任务里的每个目标算一关：`levels` = 目标总数，`passed` = 达成数。`raw` 里放每个目标的判定结果（机器可读，便于以后分析）。
- `hostOrigin` 用 `load` 消息给的值，不要用 `"*"`。

### 3.4 任务描述（建议格式 `simulearn.task/1`）

```json
{
  "format": "simulearn.task/1",
  "title": "把 3 号母线电压调进允许范围",
  "allow": { "tap": ["T1"], "shunt": ["C3"] },
  "objectives": [
    { "id": "v3", "text": "最大负荷时 3 号母线电压在 0.95～1.05 pu", "check": { "kind": "bus_vm_range", "bus": "bus-3", "case": "max", "min": 0.95, "max": 1.05 } },
    { "id": "v3min", "text": "最小负荷时不超过 1.05 pu", "check": { "kind": "bus_vm_range", "bus": "bus-3", "case": "min", "max": 1.05 } },
    { "id": "taps", "text": "分接头最多调 2 挡", "check": { "kind": "tap_steps_max", "element": "T1", "max": 2 } }
  ],
  "hints": ["先算最大、最小负荷两种情况需要的分接头电压，再取平均"]
}
```

- **判定在内核里做**：按学生最后一次提交的参数在内核里重算一遍再核对，不信页面自报的数字。
- `check.kind` 先做这几种就够第一批实验用：母线电压范围、支路功率 / 电流上限、网损上限、分接头挡数、补偿容量上限、经济调度的出力或 λ 与参考值的误差。

### 3.5 版本

拓展清单写明支持的约定版本；宿主遇到不支持的版本就提示更新，不硬跑。

## 4. 第三阶段：给这门课的教学能力

课程是《电力系统分析》稳态部分。按这个顺序做：

1. **教材风格的输电网算例**：多电压等级（110 kV 线路 + 降压变压器 + 10 kV 负荷侧）、变压器分接头按挡（110 ± 2×2.5%）、可分组投切的并联电容、带无功上下限的 PV 机组。结果展示：各母线电压（kV 和标幺值）、支路功率和损耗、电压分布图。
2. **试点：第十二章调压实验**：一个 4～5 节点网络（降压变电所带分接头、负荷侧可投电容），最大 / 最小负荷两种运行方式，配 §3.4 那样的任务。参考教材例 12-3（110 ± 2×2.5% / 6.3 kV，阻抗 2.44 + j40 Ω，最大负荷 28 + j14 MV·A、最小 10 + j6 MV·A，高压侧 110 / 113 kV，低压母线 6.0～6.6 kV，结果选 107.25 kV 挡）。
3. **第十四章经济调度**：二次耗量特性 + 出力上下限，显示 λ（单节点时就是等微增率）；参考例 14-3（三厂共带 700 MW，2 号厂越上限取 250 MW，其余 450 MW 在 1、3 号厂间按等微增率分配：P1 ≈ 176 MW、P3 ≈ 274 MW，λ ≈ 0.5465）。
4. **第十一章牛顿-拉夫逊迭代过程**（价值高、工作量大）：现在的潮流用 Ipopt 求解，不给中间过程。要在内核里自写极坐标牛顿-拉夫逊，逐次输出功率不平衡量、雅可比、修正量、电压，并能和 P-Q 分解法、高斯-赛德尔对比收敛；用教材例 11-5（4 节点：1、2 为 PQ，3 为 PV，4 为平衡节点 1.05∠0°）对拍每一次迭代，最终结果再和 PowerModels 对拍。
5. **金标准**：每个教材算例都在 `contracts/grid/` 里加用例，数值取自教材例题，改内核先看它红不红（沿用现有做法）。

## 5. 工程与发布

- 保留现有门禁：金标准契约测试、严格 ESLint、类型检查、vitest、包体积门禁；给拓展包也加体积门禁。
- **CI**：在 Windows 构建机上构建可移植包（预编译镜像一次 20～40 分钟，缓存 Julia depot），产出 zip + sha256；再在一台干净的构建机上冒烟测试：解压、启动、健康检查、跑一次潮流、跑一个任务判定。
- **发布**：zip 和清单（版本、大小、sha256、约定版本、最低宿主版本）放到知帆的下载站 R2（建议路径 `desktop/ext/simulearn-grid-<版本>.zip` 和 `desktop/ext/manifest.json`），**清单最后传**——和知帆客户端发版同一个顺序。谁来传由两边商定。
- 日志写数据目录、按大小滚动；崩溃时留下可以让学生发给老师的报告文件；不自动上报。
- 仓库里现有的 `CLAUDE.md` / `AGENTS.md` 是通用的多智能体框架模板（要求开 swarm 等），和这个产品的开发约定无关，新管线开工前建议换成这个项目自己的说明。

## 6. 里程碑与验收

| 阶段 | 内容 | 验收 |
|---|---|---|
| M0（1～2 天） | 可移植打包验证 | §2.1 的数字全部测出；在第二台电脑上跑通 |
| M1（约 1 周） | 拓展包 + 启动约定 + 令牌 + 嵌入模式 + 成绩回传 | 按 §3 在知帆客户端里打开一个内置算例，完成后成绩出现在知帆学情里；拒绝不带令牌的请求 |
| M2（约 1 周） | 第十二章调压试点算例与任务判定 | 例 12-3 金标准通过；任务判定在内核里完成；知帆课堂里能做完这个实验 |
| M3 | 经济调度、牛顿-拉夫逊迭代过程、更多章节 | 例 14-3（含越限处理）、例 11-5 逐次迭代金标准通过 |

知帆这边同步要做（由知帆的开发负责）：客户端「拓展」管理（清单、下载、校验、安装 / 更新 / 卸载）、按需启动和关闭 Julia 进程、课堂里的「仿真实验」场景（没装时提示安装、只用网站时提示去客户端）、课程包里的实验目录（实验 ↔ 讲次 ↔ 知识点）、对接约定定稿。

## 7. 不要做的

- 不并进知帆仓库，不让 SimuLearn 依赖知帆的代码。
- 不把网关或内核直接暴露到公网。
- 不让 SimuLearn 知道课程、账号、成绩存储。
- 不塞进知帆的安装包（知帆约定：安装包不内置大资源）。
- 不用按本机 CPU 编译的预编译镜像去分发。
- 不在页面里自报分数当最终成绩（判定在内核里做）。
