# 电路案例库

电路拓展（simulearn-lab）内置了一套教学案例，按邱关源、罗先觉《电路》的章节编排，每个案例是书中一道例题的电路和参数。学生打开就能做，不用自己搭电路。

## 课程里怎么放

课程包里加一个交互场景，`project` 写成 `{"library": "qiu-circuits"}`：

```json
{ "type": "extension", "ext": "simulearn-lab", "minVersion": "0.5.1",
  "experiment": "circuit-cases", "project": { "library": "qiu-circuits" } }
```

- 一个场景就是整个案例库：学生先看到按章分组的案例列表，自己点进去做。
- 不要给这个场景配 `task`：电路实验还不会判分，配了页面会提示课程作者去掉。
- 本地调试：`node scripts/fake-zhifan-host.mjs --entry <程序目录>\bin\simulearn-lab.exe --id simulearn-lab --library qiu-circuits`，或开发态 `#/embed?library=qiu-circuits`。

### 还没有电路课时：独立课堂资源包

主站上没有电路课，电路课的学生也未必有知帆账号，所以先用一个独立的课堂资源包给入口：

```bash
node scripts/circuits-course-kit.mjs --verify   # 写到 dist/course/circuits/：电路仿真实验-<版本>.zip 和 给老师的说明.md
```

- 包里两页：一页使用说明，一个案例库场景（`experiment` 固定为 `circuits-case-library`，`minVersion` 0.5.2：草稿跨重启保留从这一版起）。课程身份 `circuits` / `simulearn-circuits-lab`，以后发新版本这两个不能变。
- 老师把 zip 发给学生，在知帆客户端「课程 → 导入课堂资源包」导入；不登录（访客）也能导入、装拓展、做实验。侧栏的课程名会显示成 `circuits`（本机导入、不在「我的课程」里的课程，客户端拿课程编号当名字）。
- 版本号默认取当天日期加 `.1`，内容一样时重复生成逐字节相同；改了内容要换版本号（`--version`），知帆拒绝导入同一版本、内容不同的包。
- `--verify` 用知帆客户端自己的 `importPackage` 导入到临时目录核对，需要本机有 course-site 仓库（`--course-site` 指定）。

## 学生怎么用

- **电路结构固定**（与课堂电路一样，D19）：不能增删元件和连线，点元件可以改参数，元件可以拖动摆放。
- 每个案例打开时已选好教材这一节讲的分析方法（网孔法、结点法、戴维宁、相量……），也可以在工具栏换别的方法对比。
- 左上角的**案例说明**：这个电路讲什么、「动手试试」改哪些参数、教材给出的结果（运行后对照），以及与教材不同的地方（例如交流读数是峰值）。可以收起。
- 改过参数的案例在列表上标「改过参数」，下次进来接着上次的改动；「恢复初始电路」把电路和分析设置都恢复成案例初始的样子。
- 「案例列表」回到列表；重新打开这个实验时，直接回到上次做的案例。
- 草稿、「改过参数」标记和上次打开的案例都由内核存进拓展的数据目录（`store` 接口），关掉知帆客户端再打开也还在（电路 0.5.2、配电网 0.5.3 起；更早的版本存在页面的本地存储里，而客户端每次启动给拓展页面换端口，重开就读不到）。卸载拓展时选择删除数据会一起清掉。

## 课堂演示（老师用）

有些案例的说明卡里多一栏「课堂演示」，点开后全屏逐步讲一个变换过程。老师点「下一步」（或按 →、空格）翻一步；画布上同一个元件跨步平滑挪位，新元件淡入、去掉的淡出，读数都是内核现算的。

| 案例 | 演示 | 内容 |
|---|---|---|
| 例 2-2 | Y-Δ 变换、Δ-Y 变换 | 两种方向各化一遍桥形电路，每一步的 R12 都是 15 Ω |
| 例 2-3 | 电源等效变换 | 图 2-15 a→e：电压源串电阻 ↔ 电流源并电阻，每一步 i 都是 0.5 A |
| 例 3-1 | KVL 与参考方向 | 任选网孔或外回路、顺时针或逆时针，逐个元件记 ±u，走完一圈 Σu = 0 |
| 例 4-7 | 含受控源的戴维宁与诺顿 | 开路求 uoc、短路求 isc、外加电源法求 Req，以及「受控源也置零」的错误做法 |
| 例 4-8 | 戴维宁等效四步 | 断开负载 → 求 Uoc → 置零求 Req → 接回负载，四个 RG 一次算完 |

- 演示只读，不改学生的电路；「退出演示」回到案例。
- 投影时尽量用全屏浏览器窗口：画面按所有步骤的电路一次适配，窗口越大字越大。

## 案例怎么保证和教材一致

每个案例都带「核对点」（教材给出的结果及容差），`packages/lab-web/src/cases/cases.e2e.test.ts` 用页面同一套代码构造请求、交给真实内核算、逐个核对；说明卡里的「教材结果」就是这组数。教材只列了方程没给数的，按教材数据算出并在说明里标 *。

演示的每一步读数同样带期望值：`src/cases/demo/demos.e2e.test.ts` 逐步交给内核核对（`DEMO=<案例 id>.<演示 id>` 只跑一个）；KVL 演示的回路是否闭合、两个方向的 Σu 是否为 0 由离线测试 `demoData.test.ts` 检查。

## 新增案例

在 `packages/lab-web/src/cases/data/` 加一个 JSON（格式见同目录 `../types.ts`），然后：

```bash
npx vitest run src/cases/cases.test.ts
LAB_E2E=1 CASE=<案例 id> npx vitest run src/cases/cases.e2e.test.ts
```

说明文字用自己的话写，只引用例题号和数值，不搬教材原文。

新增演示：在 `src/cases/demos/` 加 `<案例 id>.<演示 id>.json`（格式见 `src/cases/demo/types.ts`），并在案例 JSON 的 `demos` 里登记。跨步保留的元件用同一个 id，类型和旋转都别变（换了类型会当成新元件，旧的淡出、新的淡入）；卡片带读数时约 160×195 px（演示里电源卡片的 ΔV 行隐藏了，同高），布局时行距留够，别让连线贴着卡片走。改完用 `node scripts/demo-layout-check.mjs` 逐帧查重叠、穿线和出画面。
